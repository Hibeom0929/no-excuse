# No Excuse — Attendance & Fine Tracker

친구들과 그룹을 만들고, 각자 시간표를 올려서 수업마다 스스로 "출석 도장"을 찍는 앱입니다.
제시간에 도장을 못 찍으면 자동으로 벌금이 부과되고, 억울한 사정이 있으면 해명을 올려 팀원 투표(과반수)로 벌금을 면제받을 수 있습니다.

## 빠른 시작

처음이라면 **[SETUP.md](./SETUP.md)** 를 먼저 따라 하세요. Supabase 프로젝트를 만들고 `.env.local`을 채우는 과정이에요 (5분 정도 걸려요).

```bash
npm install
npm run dev
```

## 주요 기능

- **이메일·비밀번호 로그인** — iPhone 홈 화면 앱 안에서 바로 가입하고 로그인합니다. Supabase의 이메일 확인 설정을 켜면 처음 가입할 때만 확인 링크를 누릅니다. 기존 매직링크 계정은 비밀번호 재설정으로 전환할 수 있어요.
- **한국어/영어 전환** — 우측 상단의 KR/EN 버튼으로 즉시 언어를 바꿀 수 있어요.
- **그룹 생성/참여** — 그룹을 만들면 6자리 초대코드가 생성되고, 친구들은 이 코드로 참여합니다.
- **안전한 그룹 관리** — 일반 멤버는 그룹을 나갈 수 있고, 방장은 그룹장 위임·그룹 종료·복구·영구 삭제를 할 수 있습니다. 나간 멤버의 과거 기록은 보존됩니다.
- **다중 화폐** — 벌금을 KRW, SGD, USD 등 여러 화폐 중 선택해서 설정할 수 있어요.
- **시간표 등록/수정** — 멤버 각자 자신의 요일/시간/수업명을 등록하고, 나중에 수정할 수도 있습니다.
- **시간표 삭제/복구** — 수업을 지워도 과거 출석과 벌금 기록은 보존되며, 삭제한 수업을 다시 복구할 수 있습니다.
- **출석 체크(도장 찍기)** — 수업 시작 10분 전 ~ 종료 시각까지 체크인 가능. 잘못 눌렀으면 본인이 취소할 수 있고, 그룹 설정에 따라 인증샷 첨부를 필수로 만들 수도 있어요.
- **자동 결석 처리 + 벌금 부과** — 수업 종료 시각이 지나도록 체크인이 없으면 자동으로 결석 처리되고, 그룹에서 설정한 금액만큼 벌금이 부과됩니다.
- **해명 + 투표** — 결석한 사람이 사유를 적어 해명을 요청하면, 다른 멤버들이 인정/반려 투표를 하고 **과반수 인정 시 벌금이 자동 면제**됩니다.
- **중복·재시도 방지** — 결석 한 건에는 해명 요청 하나만 생성됩니다. 첫 표는 재시도로 덮어쓰지 않으며, 투표와 결과·벌금 면제를 DB에서 한 번에 처리합니다. 전원 투표 후 동률이면 반려됩니다.
- **해명 상태 유지** — 투표한 요청도 결과 대기 상태로 표시하고, 오늘 결정된 요청은 승인/반려 결과를 보여줍니다. 구버전 모바일 앱의 제출·투표 호출도 DB에서 검증하고 중복을 방지합니다.
- **다른 멤버 현황 보기** — 다른 멤버의 출석 기록을 읽기 전용으로 확인할 수 있어요 (수정은 불가).
- **오늘 현황 / 전체 기록 구분** — 오늘 현황에서 팀원을 누르면 오늘 수업만 표시하며, 과거 출석은 ‘전체 기록’으로 따로 확인합니다. 홈 화면 앱을 다시 열면 날짜와 데이터를 갱신합니다.
- **벌금 장부** — 이번 학기 누적 벌금과 미정산 금액을 확인할 수 있고, **총무(방장이 지정)** 만 입금 확인 처리를 할 수 있어요.
- **실시간 동기화** — 친구가 체크인하거나 투표하면 내 화면에도 곧바로 반영돼요 (Supabase Realtime).
- **동기화 오류 보호** — 조회 실패 시 기존 기록을 빈 목록으로 덮어쓰지 않고 마지막 정상 기록과 재시도 안내를 표시합니다.
- **모바일 앱 설치** — iPhone과 Android에서 홈 화면에 추가하면 전용 아이콘과 전체 화면으로 앱처럼 사용할 수 있어요.
- **수업 시작 알림** — 기기에서 직접 알림을 켜면, 아직 출석하지 않은 수업이 시작할 때 한 번 알려줍니다. 앱이 닫혀 있어도 수신할 수 있고, 누르면 해당 그룹의 오늘 출석 화면을 엽니다. 알림만으로 출석이 처리되지는 않습니다.
- **우리 팀의 하루** — 사진으로 출석하면 같은 사진을 팀 스토리로 공유합니다. 업로드 후 24시간이 되면 스토리와 동그라미가 사라지고, 사진이 없으면 제목도 표시하지 않습니다. 출석·벌금·투표 기록은 사진과 별도로 보존합니다.

## 휴대폰 홈 화면에 설치

배포된 HTTPS 주소로 휴대폰에서 접속하면 화면 아래에 설치 안내가 나타납니다.

- **iPhone/iPad**: Safari의 공유 버튼(□↑) → **홈 화면에 추가** → **추가**
- **Android**: 앱 안의 **홈 화면에 앱 추가** 버튼을 누르거나 Chrome 메뉴 → **앱 설치**

설치 후에는 홈 화면의 `No Excuse` 아이콘으로 바로 열 수 있고, 브라우저 주소창 없이 실행됩니다. 로컬 개발 주소가 아니라 Vercel 같은 HTTPS 배포 주소에서 설치해야 친구들의 휴대폰에서도 정상적으로 사용할 수 있습니다.

## 알아두면 좋은 점 (설계 노트)

- **투표 DB 업데이트** — 기존 프로젝트에는 `supabase/migrations/20261006000000_atomic_excuse_voting.sql`을 적용해야 합니다. 중복 해명은 원본을 삭제하지 않고 `superseded_by`로 대표 요청에 연결하며 기존 표도 보존합니다. `supabase/tests/atomic_excuse_voting.sql`은 최소 3명의 기존 그룹 멤버 프로필을 이용해 임시 데이터를 만들고, 권한·재시도·승인/반려를 확인한 뒤 전부 롤백합니다.
- **구버전 앱 호환** — `20261006010000_legacy_excuse_compatibility.sql`도 이어서 적용해야 합니다. 모바일에 캐시된 구버전이 원래의 INSERT/upsert를 보내도 동일한 본인·그룹 권한 검증과 중복 방지·결과 처리가 적용됩니다. 검증용 SQL은 최신 마이그레이션까지 모두 적용한 후 실행합니다.
- **자동이체는 미구현** — 실제 계좌 자동이체는 은행/PG(예: 오픈뱅킹, 토스페이먼츠) API 연동이 필요해 이 프로젝트에는 포함되어 있지 않습니다. 대신 벌금은 장부에 자동 기록되고, 계좌로 입금 후 총무가 "입금 확인" 버튼으로 정산 처리하는 방식으로 대체했습니다.
- **결석 자동 판정은 클라이언트가 대신 처리** — 원래는 서버 스케줄러(cron)가 할 일이지만, 지금은 그룹원 중 누군가의 브라우저가 열려있을 때 그 브라우저가 "오늘 종료된 수업 중 체크인 안 된 것"을 찾아 대신 처리해요. DB의 unique 제약으로 중복 처리는 막혀 있지만, 아무도 접속 안 한 날은 그날 결석 처리가 늦게 반영될 수 있어요. 정확하게 하려면 Supabase Edge Function + `pg_cron` 으로 서버 사이드 스케줄러를 만드는 게 좋아요.
- **인증사진** — 새 사진은 기기에서 JPEG 200KB 이하로 압축해 비공개 `attendance-stories` Storage에 한 번만 업로드합니다. DB에는 위치·서버 생성시각·만료시각만 저장하고, 사진은 스토리를 열 때 인증된 다운로드로 불러옵니다. 사진·공개 URL을 로컬 저장소나 서비스 워커 캐시에 저장하지 않습니다.
- **공개 기한과 보관 기한 분리** — 사진은 업로드 후 24시간 동안만 현재 팀원에게 공개됩니다. 이후에는 서버 권한으로 열람을 차단하고 학기 말 정리 전까지 비공개 보관합니다. 스토리가 없으면 제목과 바를 모두 숨깁니다. 실제 파일을 24시간 뒤 삭제하는 작업은 비활성화되어 있습니다. 일반 사용자에게 학기 보관 사진을 조회하는 API는 제공하지 않습니다.
- **학기 보관** — `attendance_stories.expires_at`은 공개 종료 시각일 뿐 삭제 시각이 아닙니다. 별도 `archive_delete_after`는 추후 확정할 학기 종료/다운로드 유예기간을 위한 자리이며 현재 모두 NULL(보관)입니다. 리캡 화면·학기 종료일 설정·용량 상한·학기 말 일괄 삭제는 아직 구현하지 않았습니다. 종료일과 삭제 범위를 확인한 뒤 별도 적용해야 하며, 날짜를 임의로 정하거나 사진을 자동 삭제하지 않습니다.
- **기존 사진과 구버전 앱** — 마이그레이션 이전 사진은 자동 공개·삭제하지 않습니다. 캐시된 구버전 앱에서 새로 보내는 Base64 사진은 서비스 전용 `attendance_legacy_story_photos`에 분리해 보관하고 출석 행에는 사진 본문을 남기지 않습니다. 전용 조회 함수만 24시간 내 멤버 열람을 허용합니다. 새 앱은 같은 사진 파일을 Storage에 한 번만 저장하며 리캡용 중복 업로드를 하지 않습니다. 실패/시간초과 후 남은 비공개 업로드도 자동 삭제 없이 추후 정리 대상이므로 용량 확인이 필요합니다.

## 출석 스토리 서버 설정

1. `supabase/migrations/20261016000000_attendance_stories.sql` 적용: 비공개 버킷, 서버 체크인, 멤버·만료 권한, 구버전 호환 기능. 기존 사진/출석/벌금/투표를 삭제하지 않습니다.
2. `20261016010000_story_cleanup_schedule.sql`은 적용 전 보관 정책 변경으로 비활성화한 빈 마이그레이션입니다. cron/Vault 비밀키를 만들거나 JWT 검증을 끄지 않습니다.
3. **반드시** `20261016020000_semester_photo_archive.sql`을 프론트엔드 배포 전에 적용합니다. 24시간 파일 삭제 후보 조회와 정리 함수를 무동작으로 바꾸고, 구버전 사진을 비공개 테이블에 분리합니다. 기존 24시간 정리 서버가 호출돼도 파일/출석/사진 본문을 지우지 못합니다. 정리 함수 소스도 삭제 없는 409 응답으로 변경했고 `verify_jwt=true`를 유지합니다. 스토리 운영에는 이 Edge Function 배포나 스케줄 설정이 필요 없습니다.
4. `supabase/tests/attendance_stories.sql` 실행: 임시 데이터만 사용하며 전부 롤백합니다. SQL 테스트는 실제 사진 파일을 업로드·삭제하지 않습니다.
5. 서버 설정 완료 후 프론트엔드를 배포합니다. `npm test`와 `npm run build`로 확인합니다.
6. 기존 운영 프로젝트에는 `20261019000000_fix_story_upload_path.sql`도 적용합니다. 업로드 정책의 `name`이 그룹 이름으로 잘못 해석되는 문제와 `INSERT ... RETURNING`에서 새 파일 행을 확인하지 못하는 문제를 수정합니다. 본인·현재 그룹·업로드 대기 10분/공개 24시간 제한, 비공개 버킷, 기존 기록과 파일은 유지합니다. `tests/story-upload-database.test.mjs`는 격리된 PostgreSQL에서 실제 `authenticated` 역할의 업로드·출석 확정과 익명/타인/다른 그룹/만료 접근 차단을 검증합니다. 운영 DB에 테스트용 사진이나 출석을 만들지 않습니다.

사진 업로드 수정 운영 적용 확인(2026-10-19): 위 수정 SQL 적용 후 해당 사용자의 경로에 대한 업로드·저장 결과 조건은 허용되고 타인/오래된 미확정 경로는 차단됨을 읽기 전용으로 확인했습니다. 출석·벌금·해명·투표·스토리·사진 메타데이터 6종은 적용 전후 동일합니다. 실제 휴대폰 사진 업로드 완료 여부는 사용자의 재시도로 최종 확인합니다.

로컬 화면 시험: `npx vite --config tests/story-preview.vite.ts --host 127.0.0.1` 실행 후 `/tests/story-preview.html`을 엽니다. 가짜 데이터와 생성한 샘플 사진만 사용하며 실제 Supabase로 요청하지 않습니다. 사진 열람·여러 장 이동·만료·취소·조회 실패를 시험할 수 있습니다.

## 수업 시작 알림 서버 설정

운영 서버 적용 확인(2026-10-17): 알림 DB 구조와 `send-attendance-reminders` 배포, JWT 검증 ON, 매분 예약 작업 1개 및 서버 응답 200을 확인했습니다. 발송키는 Vault에 비공개 보관하고 사용자 구독은 기본 OFF입니다. 기존 출석·벌금·해명·투표·스토리 기록은 적용 전후 동일함을 확인했습니다. 실제 iPhone의 앱 종료 상태 수신은 사용자 기기에서 별도 확인이 필요합니다.

1. `20261017000000_attendance_push.sql`을 적용합니다. 기존 출석·사진·벌금·투표는 변경하지 않습니다. 구독 정보와 발송 기록은 RLS 및 서비스 전용 권한으로 보호하며, 본인 기기의 설정만 제한된 함수로 변경할 수 있습니다.
2. `supabase/functions/send-attendance-reminders/index.ts`를 배포합니다. **JWT 검증을 켠 상태로 유지**합니다. 추가 예약 작업 비밀키가 일치해야 발송을 실행합니다. VAPID 개인키는 서버에서 생성해 Vault에 보관하며 브라우저·Vercel·GitHub에는 보내지 않습니다.
3. 운영자 확인 후 `20261017010000_attendance_push_schedule.sql`의 지침대로 이 프로젝트의 **공개 legacy anon JWT**를 SQL 세션 설정에 넣고 실행합니다. `sb_publishable_…` 문자열이나 서비스 역할 키를 쓰지 않습니다. 예약 작업용 비밀키는 DB 내부에서 생성됩니다. 새 비밀키 생성·예약 작업은 운영 적용 전에 확인을 받습니다.
4. 예약 작업은 1분 간격으로 실행됩니다. `attendance_push_settings.last_dispatch_at`, 공개키 설정 여부, 해당 cron 작업의 실행 및 HTTP 응답을 확인한 뒤 프론트엔드를 배포합니다. 사용자 구독은 기본 0개이며, 사용자가 기기에서 직접 켜야 합니다. 기존 사진 정리 작업은 켜지 않습니다.
5. iPhone/iPad는 iOS/iPadOS 16.4 이상에서 홈 화면에 추가한 앱을 열고, 오른쪽의 작은 **출석 알림**을 펼친 뒤 **꺼짐**을 눌러 권한을 허용합니다. 알림은 기기별 설정이며 로그아웃하면 현재 기기 구독을 중지합니다. 언어는 마지막으로 선택한 KR/EN을 따릅니다. 평소에는 종 아이콘과 켜짐/꺼짐 상태만 표시하고, 기기·잠금화면 안내와 오류/재시도는 펼쳤을 때 보여줍니다.

알림은 싱가포르 시간 기준입니다. 이미 출석했거나 해명 중/승인된 수업, 삭제한 수업·종료한 그룹·탈퇴한 멤버는 제외합니다. 리세스·공휴일·수업별 주차는 현재 주간 시간표에 없으므로 자동 판별하지 않습니다. 잠금화면에 수업명이 표시될 수 있음을 켜기 전에 안내합니다.

푸시는 시계 알람처럼 정확한 시각/도착을 보장하지 않습니다. 서버가 시작 후 2분 내 대상을 잡고, 재확인 후 한 번만 발송을 시도하며, 만료된 알림은 서비스 워커에서 숨깁니다. 네트워크 오류나 수신 단말의 집중 모드 등에 따라 누락·지연될 수 있습니다. 중복 방지를 위해 결과가 불확실한 발송도 무조건 재시도하지 않으며 서버 중단 후 지난 수업 알림을 몰아 보내지 않습니다. 한 번에 최대 20건, 4개 병렬로 처리하는 소규모 그룹용 구조입니다.

매분 실행은 30일 기준 약 43,200회 호출입니다. 별도 유료 푸시 API를 사용하지 않지만 Supabase의 함수 호출·DB·네트워크 사용량에는 포함됩니다. 요금제와 전체 프로젝트 사용량에 따라 한도에 도달할 수 있으므로 무료를 보장하지 않습니다. 발송 메타데이터와 cron 실행 로그도 누적되므로 사용량을 확인합니다. 이 기능에서 기존 기록이나 사진을 자동 삭제하지 않습니다.

알림 설정은 별도 오류 경계 안에 있어, 알림 화면이 실패해도 그룹·출석 화면은 유지됩니다. 브라우저 권한 요청·구독 조회/등록과 서버 요청은 각각 최대 12초 기다리고 안내와 재시도를 제공합니다. 알림 해제/로그아웃 정리는 여러 대기를 합쳐 최대 12초의 단일 예산을 사용합니다. 시간제한은 앱의 대기를 끝내는 것이며 운영체제의 권한 창 자체를 닫거나 진행 중인 브라우저 구독 처리를 취소하지는 못합니다. 늦게 완료된 구독 등록은 서버 알림 켜기로 이어지지 않습니다.

로컬 검증: `npm test`는 가짜 브라우저 및 실제 Web Push 암호화 라이브러리와 격리된 로컬 PostgreSQL(PGlite)로 권한·중복 방지·시간·발송을 시험합니다. 응답 없는 브라우저 API/서버, 늦은 구독 완료, 알림 실패 후 실제 인증 로그아웃 호출도 시험합니다. `npx vite --config tests/push-preview.vite.ts --host 127.0.0.1` 후 `/tests/push-preview.html`로 실제 컴포넌트를 확인할 수 있습니다. `?mode=install`, `unsupported`, `pending`, `error`는 안내/오류 화면을 시험합니다. `?mode=crash`는 알림 컴포넌트만 의도적으로 실패시키며, 접힌 개발자 동작 시험에서 다른 화면의 버튼이 계속 작동하는지 확인할 수 있습니다. 서버 요청과 실제 알림 권한 변경은 하지 않습니다. 실제 iPhone의 백그라운드 수신 확인은 본인 기기에서 별도로 진행해야 합니다.
